# 几微 · jiwei

> **面向大学生的课程表应用。** 手机优先、离线可用、数据只存在你自己设备上。

**在线体验** → <https://arrsk.github.io/jiwei/>
手机上打开后可以直接「添加到主屏幕」，当原生 App 一样用。

## 这是什么

一个以**课程表和今天首页**为核心的大学生日常应用。用浏览器就能打开，可以装到手机桌面，**不需要注册、不需要联网也能用**。

**为什么自己做一个**：现有的中文课程表应用几乎都是安卓原生，iOS 和电脑用户没得用；
而且大多要注册账号、上传数据。这个项目的取舍是——

- **数据只存在你的设备上**，没有任何服务器，不上传、不注册
- **一套代码同时覆盖电脑浏览器、手机浏览器、手机桌面**
- **离线完整可用**（地铁里、断网时照样看课表）

首页打开就能看到今天的日期、正在上的课、下一节课和当天课程列表；底部只显示“今天”和“课程表”，日程等扩展模块后续上线时再加入入口。

## 使用说明（不懂编程也能看）

### 打开它

| 设备 | 怎么做 |
| --- | --- |
| 电脑 | 浏览器打开 <https://arrsk.github.io/jiwei/> |
| 手机 | 同样打开这个网址，然后**添加到主屏幕**当 App 用 |

- **iPhone（Safari）**：底部「分享」→「添加到主屏幕」
- **安卓（Chrome）**：右上角「⋮」→「添加到主屏幕」

> **强烈建议加到主屏幕**：一是全屏好用，二是**不容易丢数据** ——
> 浏览器会清理"只是网页"的本地数据，而"已装到桌面"的会被当成 App 保留。

### 三步上手

1. **加课**：点课表里的**空白格子**（比如"周三 第 3 节"）→ 填课程名（只有这项必填）→「保存」。
   周次留空就是**每周都上**。
2. **看课**：顶部 `‹ 第 N 周 ›` 左右翻周，点「第 N 周」跳回本周；今天的日期是**蓝色**的。
3. **装机**：按上面的方法加到手机桌面，之后就日常用了。

> 想先看看效果？点表格上方的「**载入示例课表**」，会放进 9 门假课，随时能删。

### 常用操作速查

| 想做的事 | 怎么做 |
| --- | --- |
| 看清某一天的课（字大） | **点星期几那几个字** → 进"只看这一天"，点「← 整周」回来 |
| 改一门课 | 点课表里那门课的色块 → 改完「保存」（改的是**所有周次**） |
| 删一门课 | 点课程块 → 左下角「删除」 |
| **某一次**课停掉或改期 | 进日视图 → 点那一行右侧「**⋯ 调/停**」→ 停课 / 改期；随时可「恢复原样」 |
| 一次改好几门课 | 展开「全部课程」→「**批量编辑**」 |
| 单双周 / 跳过某几周 | 表单里「周次」下面**一排数字**，点一下切换；或用「全周 / 单周 / 双周」快选 |
| 改上课时间（如 8:00 改成 8:30） | 右上角 ⚙ → **作息时间**，逐节改 |
| 建第二张课表（主修/辅修/新学期） | 点**左上角课表名** → 新建 / 切换 / 改名 / 删除 |
| **备份（很重要）** | 右上角 ⚙ → **备份与恢复** → 导出备份 |

### ⚠️ 请务必定期备份

**你的课表只存在你这台设备的浏览器里。** 换手机、清缓存、浏览器出问题都可能丢数据。

**每学期导出一次备份**：⚙ → 备份与恢复 → 导出备份 → 存到网盘或微信收藏。
换设备时在新设备上「导入备份」即可。

### 常见问题（简版）

| 问题 | 答案 |
| --- | --- |
| 换手机会自动同步吗？ | **不会**。没有服务器就没有同步，用备份文件搬过去 |
| 别人能看到我的课表吗？ | 看不到。数据只在你设备上，我们这边什么都没有 |
| 为什么没有闹钟？ | **浏览器做不到**：网页在后台会被系统冻结，锁屏时无法保证响铃。解决办法是打包成原生 App，排在 M5 |
| 课表不见了？ | 先确认网址结尾是 `/jiwei/`、浏览器没换过、没开无痕模式；有备份就导入恢复 |
| 页面空白 / 一直转圈？ | 刷新；换网络（校园网可能拦截）；用 Chrome / Edge / Safari |
| 要钱吗？有广告吗？ | 不要钱、没广告、没有账号系统，MIT 开源 |

# 以下是项目细节

> 上面的「使用说明」是给**用的人**看的；从这里开始是给**开发者 / 想改代码的人**看的。

## 技术栈

| 层 | 选型 |
| --- | --- |
| 仓库 | pnpm workspace 单仓多包 + TypeScript |
| 前端 | React 19 · Vite 7 · Tailwind CSS v4 · Zustand |
| 本地存储 | IndexedDB（Dexie 封装），藏在仓储接口后面 |
| 数据契约 | Zod 定义模型 + 时间计算纯函数（前后端共用的唯一真相） |
| 测试 | Vitest（单元 154 个）· 自建冒烟检查（构建产物 23 项） |
| 部署 | GitHub Actions → GitHub Pages |
| 原生（计划） | Capacitor，复用同一份 `apps/web` 代码 |

## 架构要点

```
apps/web ──────────────► 唯一的客户端（React PWA）
packages/core ─────────► 数据模型 + 时间/周次纯函数（唯一时间真相）
packages/data ─────────► 仓储接口 + 存储引擎（可替换）+ 备份恢复
packages/ui ───────────► 通用组件 + 时间网格基座
packages/platform ─────► 能力适配（通知/闹钟/存储/文件）
```

**三条关键设计**：

1. **`Block` + `Occurrence` 模型**：`Block` 是唯一"占时间"的实体，课表只是 `kind='course'` 的视图。
   这样日程表、任务不需要另建一套并行模型——**加功能 = 加视图，不动核心**。
2. **时间只有一个真相来源**：所有周次、日期、冲突计算都在 `packages/core`，
   任何地方不得自己算日期，否则同一次课在不同界面会算出不同结果。
3. **存储引擎可替换**：业务代码只依赖 `packages/data` 暴露的仓储接口。
   将来从 IndexedDB 换到 SQLite 或接服务端同步，**只换一个入参**，业务代码零改动。

详见 [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) 与 [`docs/DECISIONS.md`](docs/DECISIONS.md)（9 条决策记录，每条都写了"为什么"）。

## 本地开发

```bash
# 环境：Node.js ≥ 22、pnpm ≥ 9
pnpm install
pnpm dev          # → http://localhost:5273/
```

手机上看效果：`pnpm dev` 会打印 `Network:` 局域网地址，手机连同一 Wi-Fi 打开即可。

### 已知局限（有意为之，不是缺陷）

- **手机上课程块较窄**：7 天塞进一屏，每列约 45px。看清细节请点星期几进**日视图**。
- **电脑和手机的数据不互通**：各存各的。可以手动导出备份再在另一台导入。
- **闹钟在浏览器里做不到**：见上方说明，排在 M5 用原生 App 解决。
- **iOS 上 IndexedDB 有被系统回收的风险**（WebKit #277615，Dexie 作者确认无解）。
  所以「定期导出备份」是当前唯一的兜底手段。

## 开发约定

1. **时间计算只用 `packages/core`**，不要在别处自己算日期。
2. **界面代码不许直接操作数据库**，只走 `packages/data` 的仓储接口。
3. **模块之间不许互相 import**，跨模块协作走 `core` 的类型与 `data` 的仓储。
4. **改完必须验证**：`pnpm typecheck && pnpm test && pnpm build && pnpm smoke`。
