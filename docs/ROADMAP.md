# 几微 · 路线图

> 原则：**每个里程碑结束都要能真实用起来**——不做"只有内部进展、用户看不到东西"的阶段。
> 纪律：实现 M(n) 时**不写**任何 M(n+1) 的业务逻辑，只使用已就位的模型与接口。
> 相关文档：[架构设计](ARCHITECTURE.md) · [决策记录](DECISIONS.md) · [新手使用说明](新手使用说明.md)

---

## 里程碑总览

| 阶段 | 主题 | 交付 | 你能体验到什么 |
| --- | --- | --- | --- |
| **M0** | **最小可用课表** | 单仓骨架 + 完整数据模型 + 手动录课 + 简易周视图 + 本地持久化 | ✅ **电脑和手机上真的能看到自己的课表** |
| **M1** | 课表完整版 | 多课表管理、单双周/跳过周/连堂、调课停课、表格批量编辑、日视图 + 今天卡片 | ✅ **真实学期的复杂课表也能正确显示** |
| **M2** | 手机可用与可靠性 | 安装引导、离线状态、存储保护、字号/密度设置 | 加到手机桌面后，断网也能看和改课表 |
| **M3** | 数据进出与课程导入 | JSON/CSV/ICS、课程表图片导入（先预览再写入） | 换设备能带走；不把教务账号密码交给应用 |
| **M4** | 日程与可开关模块 | 月历/时间线、考试/事件、官方模块开关和首页卡片 | 课程、事件在同一条时间线上；不用的模块可关闭 |
| **M5** | 提醒与 AI 命令草稿 | 应用内提醒、原生通知验证、AI 识别意图并生成待确认草稿 | AI 只提出“准备添加什么”，用户确认后才写入 |
| **M6** | 待办与基础记账 | 待办截止日、完成状态、收支记录和今日汇总 | 能看到最近要交什么、今天花了多少钱 |
| **M7** | 笔记、手写与识图 | 文字/手写笔记、课程关联、记账小票识图、搜索 | 上课能记，账单先识别成草稿再确认 |
| **M8** | 同步与受控插件（可选） | 多设备同步、分享、L1 开发者插件试验 | 先验证隐私、成本和权限，再开放生态或云端 AI |

> **阶段划分原则**：M0 是**垂直切片**（每层都碰、都跑通、但都只做最少），M1 才是**把课表做完整**。
> 这样第一周就能验证"模型 → 存储 → 渲染"整条链路，架构问题早暴露，而不是等全部写完才发现。

## M0 · 最小可用课表（目标：让你尽快真实用起来）

**你最终能做的事**：打开网页 → 建个学期 → 添几门课 → **看到周视图课表**；手机上打开同一地址也能看到；关掉重开数据还在。

### A. 地基
- pnpm workspace + TypeScript 严格模式；`apps/web`、`packages/{core,data,ui,platform}`
- Vite + React 19 + Tailwind v4 + 路由 + 深色模式骨架
- ESLint 规则：禁止 `features/*` 直接 import Dexie（接口隔离的强制执行）
- **完成标准**：`pnpm dev` 启动，控制台打印"存储已就绪、schema 版本 N"

### B. 模型与存储（**完整**，不缩水）
> 模型是全局最贵的部分，M0 一次做全，后续里程碑不再改结构、不再迁移数据。

- `@jiwei/core`：**完整的** Zod schema（`Semester`/`Period`/`Block`/`Occurrence`/`Alert`/`Note`/`Meta`）
- `@jiwei/core`：`materialize()` 与周次/日期纯函数（`expandWeeks`/`currentWeek`/`nextOccurrence`）+ 单测
- `@jiwei/data`：仓储接口 + Dexie 引擎实现 + schema 版本迁移（幂等）

### C. 课表功能（**最小**，只做能跑通闭环的部分）
- 学期：名称、起始日（第 1 周周一）、总周数
- 作息：默认一套常见作息（第 1~12 节），先不做编辑界面
- 录课：一门一门添加（名称、老师、地点、颜色、星期、起止节次、周次)
- 周视图：`TimeGrid` 网格渲染 + 左右切周
- 本地持久化
- **暂不做**：单双周/跳过周的录入界面（模型已支持，先用全周）、连堂的拖拽、表格批量编辑、日视图、调课

### D. 完成标准
- 电脑浏览器可访问，手机浏览器打开同一地址（局域网 IP）也能看到课表
- 添加的课程**刷新/重开后仍在**（本地库生效）
- `materialize()` 与周次计算有单测覆盖
- 断网状态下页面仍能打开（本地优先的初步验证）

## M1 · 课表完整版

**功能（在 M0 基础上补齐）**
- 修改已有课程（点课程块进入表单，改完保留原 id）
- **新建与管理课表**：建多个学期/课表，能切换、重命名、删除；每张课表各自的课程与作息互不干扰
- 课程录入补全：单双周、跳过指定周、连堂（起止节次跨多节）、复制周次
- 表格/批量编辑：一屏内改多门课
- **日视图**：手机默认；"今天"卡片显示当前/下一节课
- **当前周高亮**
- 调课/停课（`Adjustment`）：某一次课临时取消或改到别的日期/节次
- 作息时间表编辑界面

**架构要求**
- 网格用 `@jiwei/ui` 的通用 `TimeGrid`（不是课表专用）
- 页面来自 `features/timetable` 导出的 `FeatureModule`，外壳负责导航
- 所有时间计算调用 `@jiwei/core/materialize`，模块内不出现日期算法

**完成标准**
- 真实学期课表（含单双周、跳过周、连堂、调课）显示正确
- 单双周、跳过周、连堂、调课都有单测覆盖
- 多张课表并存时，切换课表不会串课、删除课表不会残留数据

**M1 收尾时发现并修掉的既有 bug**（值得记一笔，因为都属于"界面看起来对、其实数据错了"）：

| 问题 | 表现 | 修法 |
| --- | --- | --- |
| 调课重复显示 | 一次调课在原时间与新时间**各显示一遍** | `moved` 改标在原时间上，新增 `movedFrom`（ADR-009） |
| 停课/调课后仍提示"下一节" | 已经不上课了还被算进"下一节" | 新增 `isOccurrenceActive()` 统一判据（ADR-009） |
| 切换课表会串课 | `listCourses()` 返回所有学期的课 | 视图改用 `listBySemester()`（ADR-008） |
| 作息配置是全局的 | 改 A 课表作息会覆盖 B 课表 | 配置键改为按课表存（ADR-008） |

## M2 · 手机可用与可靠性

- PWA 安装说明、离线状态、持久化存储与用量提示；字号/密度设置。
- 当前已完成首页、课程表、安装/离线提示，以及设置中的字号和课表密度；M2 剩余部分主要是真机与断网验收。
- 当前导航只显示“今天 / 课程表”，已移除未实现的日程占位入口；日程功能仍按 M4 计划推进。
- **完成标准**：手机加到桌面后全屏打开，断网可看和编辑，刷新后数据仍在。

## M3 · 数据进出与课程导入

- JSON/CSV/ICS 文件进出；先做本地文件导入，不做持续订阅服务器。
- 课程表图片导入：识别只生成草稿，用户预览、修改、确认后才写入。
- 当前本地已完成 M3 第一小步：CSV 课程导入/导出、模板、字段校验、预览和确认写入；暂未推送到 GitHub。
- 当前本地又补充 ICS 日历导出和课程表图片本地预览；AI 识别尚未接入，不能把图片预览当成识图完成。
- **完成标准**：导入失败不改变旧数据；导出的文件能在另一台设备还原。

## M4 · 日程与官方模块开关

- 月历/时间线和事件、考试；与课程共用日期和 Occurrence 计算。
- 内置 `timetable`、`agenda`、`tasks`、`ledger`、`notes`、`assistant` 注册表；设置里可按需启用/关闭，关闭只隐藏入口，不删除数据。
- **完成标准**：用户能记录事件并在“今天”看到；每个官方模块有独立入口和空状态。

## M5 · 提醒与 AI 命令草稿

- 应用内提醒；Capacitor 原生通知在有真机条件后验证，Web 端继续明确降级。
- AI 助手先支持文字意图识别，输出待确认的“添加待办/日程/支出/笔记/课程导入”草稿。
- **完成标准**：AI 不直接写库、不绕过表单；每次写入都有用户确认和失败提示。

## M6 · 待办与基础记账

- 待办：截止日、课程归属、完成/逾期、首页最近事项。
- 记账：收入/支出、金额、分类、备注和今日汇总；先手动录入，金额用安全的十进制表示。
- **完成标准**：离线可用、可备份恢复，今日页能看见待办和收支摘要。

## M7 · 笔记、手写与识图

- 文字/手写/混合笔记，可关联一次课、整门课或独立保存；支持 Markdown 导出和搜索。
- 小票识图与课程表识图共用 OCR 能力层，但输出不同草稿；图片默认本地处理，云端处理逐次征得同意。
- **完成标准**：课次重建后笔记引用不丢；识图结果必须先预览确认。

## M8 · 同步与受控插件（可选）

- 先验证分享和多设备同步的隐私、删除、导出、冲突和持续成本，再决定是否服务化。
- 在 L0 内置模块稳定后，试验 L1 受控插件：manifest、权限清单、数据命名空间和卸载清理；暂不运行任意远程代码。
- **完成标准**：本地核心在服务器不可用时仍可读写；未满足成本和隐私条件就保持本地优先。

---

## 里程碑纪律

1. **一次只加一个模块**；M1 冻结期间不插队。
2. 每个里程碑结束都要能**真实用起来**，不做"半成品功能堆积"。
3. 任何"顺手也能做"的功能记入 Backlog，**不进入当前里程碑**。
4. 模型改动必须回写 [`ARCHITECTURE.md`](ARCHITECTURE.md) 第 4 节与 [`DECISIONS.md`](DECISIONS.md)。
