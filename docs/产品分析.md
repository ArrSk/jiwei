# 几微 · 产品分析：需求、竞品、变现与迭代方向

> 这份文档回答四个问题：**大学生到底有多需要它 / 竞品强在哪弱在哪 / 怎么变现 /
> 怎么做不冒犯用户的数据调研**，并据此给出迭代优先级的调整建议。
>
> 所有外部论据都在文中标注了出处，最后一节列了链接。
> **文中标了「估计」的数字是我的推算，不是实测数据** —— 请当作假设，用第五节的方法去验证。

---

## 0. 结论先行

| 问题 | 结论 |
| --- | --- |
| 需求程度 | **真实，但被高估**。它是"高价值、低频次、易替代"的工具，不是"刚需高频"。真正的窗口期只有开学前后 2~3 周 |
| 竞品优势 | 几微的优势**不在功能，而在"反面"**：不注册、不广告、不臃肿、不碰教务账号、离线可用。而竞品的差评恰好全集中在这五条上 |
| 变现 | **靠课表本身几乎不可能独立变现**。学生付费意愿低、课表打开频次低、广告会直接摧毁唯一优势。最现实的三条路是：班级/社团版、iCal+同步的买断制、开源赞助；最现实的目标其实是"自用 + 作品集" |
| 数据调研 | 分四层，**从零隐私成本的方法开始**（竞品差评挖掘 > 深访 > 主动招募问卷 > 可选的自托管统计）。绝不接入任何第三方统计 SDK |
| 迭代方向 | **把 iCal 订阅提到最前面**（用最低成本解决"没闹钟"这个最大短板），紧接着做**兼容竞品导出文件的导入**（合法地绕开"不做教务抓取"的限制）。日程/任务/笔记要等留存验证之后再动 |

**一句话**：这个项目的护城河是"**克制**"，而克制本身不产生收入 —— 所以要靠"不做坏事"换来信任，再用信任换一个很小的付费点，而不是反过来。

## 1. 需求程度分析

### 1.1 先破除一个幻觉：课表 App 是"刚需高频"吗

一篇在校园创业圈流传很广的分析把这件事说得很直白：

> "课表类App真的是'刚需高频'吗？这有点像假期我们背回家的书：不背回家觉得对不起时间，背回去了其实也不会用得到。"
> —— [《校园用户争夺战（一）：课表类App正走在下坡路上》](https://www.downol.com/dianlaoruanjian-28345)

它把学生分成三类：

| 类型 | 为什么不用课表 App |
| --- | --- |
| 学霸 | 课程早就记住了，或者直接看教务系统 |
| 学渣 | 反正也不去上课 |
| "聪明"的学生 | 开学时用一次生成课表，**截图存相册**，之后再也不打开 |

这个判断有它的道理，而且指出了一个残酷事实：**课表 App 最大的竞品不是另一个 App，是"截图 + 手机相册"。**

### 1.2 但有三个新变量，让今天的需求比十年前更真实

十年前的判断不完全适用于现在：

1. **选课制 + 学分制普及** → 同一个班每个人的课表都不一样，"我的课表"成了个人信息，不能再靠同学之间问。
2. **多校区 / 走班 / 教室分散** → "下一节课在哪栋楼"变成每天要问的问题。
3. **系统日历对"教学周"支持极差** → 单双周、第 3 周开始、第 9 周停课，这些**系统日历表达不了**。这是课表 App 目前唯一不可替代的技术缝隙。

所以我给需求强度的判断是：

| 维度 | 评价 | 说明 |
| --- | --- | --- |
| 需求真实性 | ★★★★☆ | 确实存在，学校自己都承认（见 1.4） |
| 使用频次 | ★★☆☆☆ | 开学 2~3 周很高，之后降到每天 0~1 次，很多人干脆不看 |
| 需求强度 | ★★★☆☆ | 漏看一节课的代价很高（点名、迟到），所以**价值**不低 |
| 可替代性 | ★★★★★ | 截图、系统日历、教务 App、同学群里问、班委发的 Excel |
| 付费意愿 | ★☆☆☆☆ | 见第三节的实测调查 |

**定位结论**：课表是「**高价值、低频次、易替代**」的工具。
它不适合作为一个独立的商业产品，但**非常适合作为"大学生活 App"的入口** ——
因为它是唯一一个"全校每个人都必须关心、且信息天然结构化"的东西。

### 1.3 需求的真实证据：从竞品差评里挖

判断需求最便宜的方法不是发问卷，而是看**已经在用同类产品的人骂什么**。
这是零隐私成本、零打扰的一手数据。下面是从应用汇上「超级课程表」真实用户评论里摘的原话：

| 用户原话 | 暴露出的真实需求 / 痛点 |
| --- | --- |
| "就用一个课程表，你要手机号码注册干什么？还要定位干什么？" | **不要为看课表付隐私代价** |
| "广告太多了……" | 广告容忍度极低 |
| "广告直接出现在中间正上方，直接不能切换星期（不然一点就转去其他应用）" | **广告挡住了核心操作**，这是最致命的一种伤害 |
| "本来用就只要一个课表，做这么多与课表无关的拓展服务实在离谱" | **功能臃肿 = 负价值** |
| "导入课表是做出来搞笑的吗，登了半个小时都没登上教务系统，每次都是密码错误，我都改三次密码了" | 一键导入**不可靠**，且用户在反复输密码 |
| "教务系统导入都不行了，还好用个篮子" | 依赖学校系统 = **随时失效** |
| "害我好几次迟到了" | 可靠性是底线，坏一次就流失 |
| "学校不是都有自制的软件么" | 校方自建是强力替代 |
| "如果用腻了超级课程表，那就用 wake up" | **迁移成本极低**，没有忠诚度 |
| "越来越垃圾，还不停有骗子发诈骗信息" | 校园社交/开放互动带来安全风险 |

这张表基本就是几微的产品需求文档。**竞品把自己最弱的五条全暴露了：隐私、广告、臃肿、教务依赖、可靠性。**

### 1.4 学校自己的态度：需求的另一面证据

长沙理工大学教务处在 2026 年 3 月发的声明，间接证明了需求的存在，也划出了一条红线：

> "对任何以'便捷查课表'、'快速算绩点'、'学业分析'等名义索要教务账号密码的校外服务，均应保持高度警惕，坚决拒绝提供。"
> "任何未经我校明确授权，通过任何技术手段（包括但不限于诱导学生分享账号密码、自动化脚本抓取、系统漏洞侵入等方式）非法获取、使用我校教务管理系统内数据的行为，均涉嫌违反《网络安全法》《数据安全法》《个人信息保护法》……我校保留对相关侵权主体依法追究其法律责任的一切权利。"
> —— [长沙理工大学教务处声明](https://www.csust.edu.cn/jwc/info/1101/7727.htm)

三个信息点：

1. 学校承认学生有"**便捷查课表**"的需求（否则不会有第三方去做）；
2. 学校**从未授权**任何第三方接入 —— 所以"官方合作"的宣传都是假的；
3. 这条路现在是**法律风险**，不只是技术风险。

> **这直接支持了项目 ADR-001 的决定：不做教务抓取。** 但它也带来一个必须正视的代价，
> 见 2.4。

### 1.5 需求的天花板

| 压制需求的因素 | 影响 |
| --- | --- |
| 教务抓取被学校封禁、且违法风险上升 | "一键导入"这条最能促成转化的路越来越窄 |
| 校方自建（今日校园 / 企业微信 / 教务处 App） | 学校自己把需求吃掉了 |
| iOS/Android 系统日历 + 手动录一次 | 对"只想知道几点在哪"的人够用 |
| 学生只在开学用一次 | 留存天然很差 |

**所以需求判断的落点**：不要指望"课表"本身撑起一个产品。
它只能作为**入口**，而能不能留住人，取决于入口之外那一步 —— 这正是第五节要回答的。

## 2. 竞品分析

### 2.1 竞品地图

| 竞品 | 类型 | 强项 | 弱点 |
| --- | --- | --- | --- |
| **超级课程表** | 安卓为主的老牌头部 | 教务一键导入覆盖学校多；品牌认知度高；历史上注册用户量达千万级（**2015 年前后数据：2000 万注册 / 日均 200 万**，见出处一） | 强制手机号注册、要定位；广告侵入核心操作；功能臃肿且有社交诈骗风险；被用户做成"去广告模块" |
| **课程格子** | 老牌第二 | 曾是"课表 + 轻社交"的开创者；1700 万注册 / 150 万日活（同期数据） | 转型社区/电商失败，社区活跃度崩塌；**已基本退出主流** |
| **WakeUp 课程表** | 当前 iOS 主流 | 界面干净、纯本地、口碑好；是用户在超级课程表之外的首选替代 | 生态相对单一；无跨端同步 |
| **极简课程表 / 星课程表** 等 | 新入局者 | 主打"极简""Watch 联动" | 功能面窄，多为个人/小团队作品 |
| **系统日历（iOS/Android/鸿蒙）** | 系统自带 | 零安装、系统级提醒、锁屏可见 | **表达不了单双周/教学周**；录入麻烦 |
| **今日校园 / 企业微信 / 教务处 App** | 校方官方 | 数据最准、学校背书 | 体验普遍差，只解决"看"，不解决"用" |
| **滴答清单 / Notion / 飞书** | 通用效率工具 | 能力强、跨端同步好 | 要自己建模，课表场景没有开箱即用 |
| **截图 + 手机相册** | **真正的最大竞品** | 零成本、零学习、够用 | 不能搜、不能改、不能提醒 |

### 2.2 竞品的护城河有多深？

要诚实：**这些竞品几乎没有护城河，只有规模。**

- 用户迁移成本极低（差评里直接说"用腻了就换 wake up"）；
- 数据是用户自己录的，随时可带走；
- 功能不存在技术壁垒（几微用几周就做出了核心功能）。

所以对竞品来说，**唯一能留住用户的是"习惯"和"学校覆盖数"**，
而这两样对新入场者都是坏消息，除非走一条完全不同的价值主张 —— 那就是几微现在这条路。

### 2.3 几微的真实优势（逐条判断可持续性）

| 优势 | 用户价值 | 可持续性 |
| --- | --- | --- |
| **零注册、零账号** | 直接命中"你要我手机号干什么"的怨气 | 🟢 高 —— 有服务器才能同步，所以竞争对手**很难**为了体验而放弃账号体系 |
| **零广告、无开屏** | 直接命中"广告挡住切换星期" | 🟢 高 —— 广告是头部竞品的主要收入，它们退不回来 |
| **不碰教务账号密码** | 规避盗号、诈骗、法律风险 | 🟢 高 —— 学校已公开定性为非法，这条会越来越值钱 |
| **离线完整可用** | 地铁、教学楼弱网照样看 | 🟡 中 —— 竞品也能做，但它们的架构偏云端 |
| **数据只在本机** | 隐私焦虑的解药（25% 的用户因隐私拒付/拒用，见 3.1） | 🟢 高 —— 这是架构级选择，改起来代价极大 |
| **一套代码覆盖电脑/手机/桌面** | iOS 和电脑用户有得用（竞品几乎都是安卓优先） | 🟡 中 |
| **东西少、上手快** | 反对臃肿 | 🟡 中 —— "少"既是优点也是天花板 |

**共同点**：这些优势全部来自"**不做某件事**"。
这类优势的特点是——**极难被抄袭，但也极难变现**，因为用户不会为"你没做坏事"付费，
他们只会因此**留下来**。

### 2.4 几微最大的劣势（必须正视）

| 劣势 | 后果 |
| --- | --- |
| **不能一键导入教务** | 用户第一次打开要**手动录 8~12 门课**。估计 5~10 分钟。竞品是 10 秒。**这是最大的一处流失点，可能直接损失大部分潜在用户** |
| 没有锁屏闹钟 | 已经在 README 里如实说明，但这是很多人的第一需求 |
| 没有 iOS 原生包（目前只是 PWA） | App Store 搜不到，传播受限；iOS 存储还有被回收的风险 |
| 手机与电脑数据不通 | 换设备要手动导出导入 |
| 单人项目、无运营 | 没有推广渠道，只能靠口碑 |

> **诚实的结论**：几微现在做的是**"给愿意忍耐手动录课的那部分人"**的产品。
> 这部分人不多，但他们的需求（干净、隐私、可靠）被现有产品**系统性地亏待**了。

### 2.5 一个可以绕过最大劣势的办法（重要）

"不能抓教务"和"必须手动录课"之间，其实有一条**合法的中间路**：

> **兼容竞品的导出文件。**
> 让用户先在 WakeUp / 超级课程表里用它们的"一键导入"拿到课表，
> 再从那里**导出**成文件，然后在几微里**导入**这个文件。

这样：

- 用户拿到"一键"的便利（在别的 App 里完成）；
- 几微**从头到尾没碰过教务账号密码**，法律与道德风险为零；
- 代价只是多两步操作，比手动录 10 门课好得多。

这条路不需要任何授权，也不违反学校声明（声明禁止的是"索要教务账号密码"和"非法侵入"）。
**建议把它作为 M3 的最高优先级之一**（详见 5.1）。

## 3. 变现手段

### 3.1 先看清现实：大学生愿意为什么付费

封面新闻 2026 年 6 月调查了 20 位成都大学生，问"AI 工具每月 38 元你付不付"：

> 45% 回复免费版够用，没必要付费；30% 认为**考试周、论文季、找工作阶段**愿意付费尝试；20% 处于观望；5% 调侃穷但想用。
> 总结：约**七成不会立即付费**，真正愿意长期订阅的大概**三成**。
> 另外：40% 表示**"付费之后还限制次数"最容易引发不满**；25% 会**因隐私问题被劝退**。
> —— [封面新闻调查](https://cbgc.scol.com.cn/news/7701457)

（样本只有 20 人、单个城市、且问的是 AI 工具不是课表，只能当**方向性参考**。）

对课表 App 的推论：

| 结论 | 对产品的要求 |
| --- | --- |
| 订阅制很难 | 不要做"每月 X 元"，学生会算得很清楚 |
| "场景性付费"有空间 | 付费点要绑定**具体时刻**（开学导入、考试周、毕业前） |
| **限次数是最招骂的** | 要做就做**买断/一次性**，不要给功能加额度 |
| **隐私是付费意愿的杀手** | 一旦要账号、要上传，连免费用户都会跑 |

### 3.2 变现方案清单（按可行性排序）

| # | 方案 | 天花板 | 风险 | 评价 |
| --- | --- | --- | --- | --- |
| 1 | **不变现**（自用 + 作品集） | 0 元 | 无 | **最现实**。这个项目对求职的价值远大于直接收入 |
| 2 | **开源赞助**（爱发电 / GitHub Sponsors） | 低（估计每月几十~几百元） | 无 | 与"不开广告"的价值主张完全一致，可以做 |
| 3 | **买断制高级版**（一次性 ¥18~38） | 低 | 低 | 必须绑定"真需要服务器"的能力（见 3.3） |
| 4 | **班级 / 社团版** | 中 | 低 | **最值得试**：付钱的是班委/辅导员，用的是全班 |
| 5 | 校园流量导流（CPA / 信息流广告） | 中 | **高** | 与核心价值直接冲突，**建议永久放弃** |
| 6 | 数据变现 | 低 | **法律+道德红线** | **明确不做**，也不要有任何中间态 |

### 3.3 如果要做付费，唯一说得通的产品形态

付费点必须**不是**"解锁本来就该有的功能"，而是"**需要成本、因此必须收费**"的能力：

| 付费能力 | 为什么可以收费 | 对应里程碑 |
| --- | --- | --- |
| **多设备同步** | 需要一台服务器，成本真实存在 | M8 |
| **iCal 订阅链接（长期可用）** | 需要服务端持续生成订阅源 | M3 |
| **班级/社团共享课表** | 需要服务端存储与分享 | 新方向 |
| 主题、字号、图标 | 开发成本一次性 | M2 —— **不建议收费**，容易招骂 |

**不要卖**：导出备份、离线使用、深色模式、基本编辑功能。
这些一旦收费，就直接背叛了现在所有"干净"的宣传口径。

### 3.4 算一笔账（估计，用于校准预期）

假设做到 1000 个真实活跃用户：

| 方案 | 假设 | 收入 |
| --- | --- | --- |
| 开源赞助 | 1% 的人赞助 ¥20 | ≈ ¥200（一次性） |
| 买断制 ¥25 | 3% 转化 | ≈ ¥750（一次性） |
| 班级版 ¥199/学期 | 覆盖 10 个班 | ≈ ¥2,000/学期 |
| 开屏广告 | 1 万次展示 | 几元~几十元 |

结论：**除"班级版"之外，都无法覆盖维护成本**。
所以对这个项目，"变现"的现实意义是：**验证能不能被愿意付费的人接受**，
而不是真的靠它生活。

### 3.5 明确画红线的三件事

写在这里，是为了将来（包括我自己）不自我说服：

1. **不卖数据、不做用户画像、不接第三方统计 SDK。**
2. **不做开屏广告、不做信息流广告、不在核心操作路径上放任何商业内容。**
3. **永不索要教务系统账号密码**，也不做任何形式的自动化抓取。

这三条是产品的立身之本。破任何一条，几微就变成了它当初要反对的那个东西。

## 4. 可接受的数据调研方案

### 4.1 原则：数据承诺本身就是产品的一部分

README 和使用说明里已经写了：**"不上传、不注册、数据只在你设备上"**。
这句话是卖点，不是修辞。所以：

> **任何埋点都是对用户的例外，必须满足三个条件：用户知情、默认关闭、拒绝后功能不减。**

违反这条，损失的不是合规性，是**唯一的产品优势**。

### 4.2 四层方案（从零成本到有成本，按性价比排序）

#### 第 1 层：零隐私成本（**现在就做，性价比最高**）

| 方法 | 怎么做 | 能回答什么 |
| --- | --- | --- |
| **竞品差评系统性挖掘** | 抓取 App Store / 应用汇 / 酷安 / 贴吧上竞品的**全部差评**，建 CSV：`日期 / 竞品 / 星级 / 原文 / 痛点标签 / 场景`。目标 200 条起，按标签聚合 | 真实痛点排序、功能优先级、措辞素材 |
| **学校官方文件** | 各校教务处通知、学期制度、选课规则变化 | 需求的结构性变化 |
| **GitHub Issues / Discussions** | 让用户主动提，公开透明 | 愿意发声的那部分用户 |
| **搜索引擎 / 社交平台话题** | "课程表 App 推荐""早八""教务系统崩了" | 场景与情绪 |

> 这一层**不接触任何用户数据**，拿到的却是最真实的需求，应该占调研工作量的 60%。

#### 第 2 层：主动招募 + 知情同意

| 方法 | 规模 | 要点 |
| --- | --- | --- |
| **半结构化深访** | 10~20 人 | 一次 30 分钟，问"上一次打开课表是什么时候、为什么"，**不要问"你想要什么功能"** |
| **在线问卷** | 100~300 份 | 腾讯问卷/问卷星；**不收集姓名、学号、学校全称**；只问行为与场景 |
| 同学群 / 校园大使 | 1~3 个学校 | 找愿意反馈的人，避免自嗨 |

**知情同意怎么写**（最小可用版，放在问卷和访谈开头）：

> 这是一个人开发的学习项目，我想知道课表 App 到底哪里不好用。
> 这份问卷**不收集**你的姓名、学号、手机号，也没有任何登录。
> 结果只用来排功能优先级，不会对外发布原始数据，30 天后删除。
> 你可以随时停止，不填任何一题。

#### 第 3 层：可选的、默认关闭的产品内统计（**建议 M2/M3 阶段不做**）

如果将来真的有 100+ 真实用户、且第 1、2 层回答不了问题时，才可以考虑：

| 要求 | 具体做法 |
| --- | --- |
| 自托管 | 用 [Umami](https://umami.is/) 或 Plausible 的**自托管**版本，**不接入任何第三方 SaaS** |
| 只记事件名 + 计数 | 例如"添加课程""切到日视图"，**不记设备 ID、不记时间戳序列、不记课程内容** |
| 默认关闭 | 首次启动用大白话告知 + 一键关闭；关掉后功能完全一样 |
| 不做画像 | 不做分群、不做漏斗归因、不做 A/B 实验 |
| 可查可删 | 提供"我贡献了什么数据"的查看页 |

**技术上的一条硬规则**：不要为了省事接入第三方统计 SDK —— SDK 本身就是数据外流通道，
而且会污染"无服务器"的架构叙事。

#### 第 4 层：明确不做

- ❌ 设备指纹 / 跨站标识
- ❌ 行为序列、点击热图、录屏回放（FullStory 类）
- ❌ 任何形式的数据出售、共享、用于训练模型
- ❌ 在用户不知情的情况下上传任何东西

### 4.3 一个 8 周的调研计划（可执行版）

| 周 | 动作 | 产出 |
| --- | --- | --- |
| 第 1 周 | 建"竞品差评库"，先抓 100 条 | `research/competitor-complaints.csv` |
| 第 2 周 | 补齐到 200+ 条，打标签做聚合 | 痛点排序表（Top 10） |
| 第 3 周 | 写好访谈提纲与知情同意 | 访谈脚本 |
| 第 4~5 周 | 深访 10 人（同学 / 群友） | 10 份访谈记录 + 归纳 |
| 第 6 周 | 发问卷（目标 100 份） | 问卷结论 |
| 第 7 周 | 把三份数据交叉验证，找出**重复出现 3 次以上**的结论 | 结论清单 |
| 第 8 周 | 据此重排里程碑，写进 ROADMAP | 迭代方向 |

> 注意：**第 7 周的"重复出现 3 次以上"是硬门槛**。
> 只在一处出现的说法只能进 Backlog，不能进路线图 —— 这是防止"被一个用户带偏"的纪律。

### 4.4 调研必须回答的 6 个问题

不问这 6 个，调研就是闲聊：

1. 你上一次打开课表 App 是**什么时候**？当时在干什么？（测真实频次）
2. 开学第 3 周之后你还会打开吗？为什么？（测留存衰减）
3. 你现在用什么替代？（截图 / 系统日历 / 教务 / 问同学）
4. 手动录 10 门课，你能忍吗？录到第几门会放弃？（测最大流失点）
5. 你愿意为**什么场景**付费？（问场景，不问功能）
6. 你最怕什么？（丢数据 / 隐私 / 广告 / 不准）

## 5. 由此确定的迭代方向

### 5.1 迭代优先级调整建议

现状（`docs/ROADMAP.md`）是 M2 → M3 → M4 → M5 → M6 → M7 → M8 顺序做。
基于上面的分析，我建议**重排**：

| 优先级 | 做什么 | 为什么排这个位置 | 成本 |
| --- | --- | --- | --- |
| **P0** | **M3 前半：iCal 日历订阅** | 用**最低成本**解决"没有闹钟"这个最大短板 —— 课表订阅到系统日历后，闹钟由系统负责，且锁屏可见、跨设备可见。同时它还顺手解决了"电脑和手机数据不通" | 低 |
| **P0** | **M2：安装引导 + 离线验证 + 字号/密度** | 直接影响留存，成本低 | 低 |
| **P0** | **M3 后半：兼容竞品导出文件的导入** | 命中 2.4 里最大的流失点（手动录课），且**合法绕开教务抓取** | 中 |
| **P1** | M7 笔记（**只做一种粒度**：绑定某一门课） | 课表是低频，笔记是高频；这是唯一能真正提升打开频次的功能。但**先做最小版**验证 | 中 |
| **P2** | M4 日程表 | 有价值，但不解决核心痛点，属于"扩张"而非"补短板" | 中 |
| **P3** | M5 闹钟（Capacitor 原生包） | 成本最高（需要 Android Studio 环境、要发版），只有在 iCal 方案被验证不够用时才做 | 高 |
| **P4** | M6 任务 | 与笔记有重叠，可合并考虑 | 中 |
| **P5** | M8 多设备同步 | 一旦做服务器，等于放弃"无服务器"这个最大卖点，**要极其慎重** | 很高 |

**核心变化：把 M3 提到 M2 之前/并行，把 M5 往后推。**
理由：M5（原生闹钟）成本最高、平台风险最大，而 iCal 订阅能用 5% 的成本拿到 70% 的效果。

### 5.2 三个"不要做"

历史已经替我们付过学费：

| 不要做 | 依据 |
| --- | --- |
| **不要做校园社交 / 匿名社区** | 课程格子的"Here"团队解散、超级课程表的"跳蚤市场"日发帖量跌到个位数；两家头部都在这上面翻过车。几微更没资源 |
| **不要做电商 / O2O 导流** | 学生"本身不具备任何忠诚度，谁便宜买谁"（原话出自出处一），这条路需要烧钱 |
| **不要为了留存而堆功能** | 竞品差评里"与课表无关的东西太多了"是高频抱怨。"轻"是几微唯一的护城河，堆功能等于自杀 |

### 5.3 如果要找"第二曲线"

正确的扩张方向是**把"课表"扩展成"学期"**，而不是扩展成"校园"：

```
课表  →  日程  →  任务  →  笔记
（我在哪上课）（我要去哪）（我要交什么）（我学到了什么）
        ↑ 全部围绕"我自己这一个学期"展开
```

而**错误**的方向是：

```
课表 → 校园社交 / 二手市场 / 兼职 / 表白墙   ← 历史证明全部失败
```

判断标准很简单：**新功能是回答"我这学期发生了什么"，还是回答"别人在干什么"？**
前者做，后者不做。

### 5.4 应该盯什么指标

课表 App **不能看 DAU**（它本来就低频）。应该看：

| 指标 | 为什么 | 健康线（建议，待验证） |
| --- | --- | --- |
| **开学第 4 周留存** | 直接测"是不是只用一次就丢" | > 60% 算好 |
| **备份导出率** | 测信任度：愿意为它做备份，说明真的在用 | > 20% 算好 |
| iCal 订阅使用率 | 测 P0 方案是否命中痛点 | > 30% 说明方向对 |
| 手动录课完成率 | 测 2.4 的最大流失点 | 录满 5 门的人占比 |
| NPS（愿意推荐给同学吗） | 口碑是唯一推广渠道 | > 30 |

> **不要**用"总注册数""下载量"这类数字自我安慰 —— 本项目连账号都没有，这些数字也不存在。

## 附：本文件的局限

诚实标注，避免被当成结论滥用：

1. **竞品用户量数据是 2015 年前后的**，只用于说明品类历史，不代表当前规模。
2. **付费意愿调查样本仅 20 人、单个城市**，且问的是 AI 工具，只能作方向性参考。
3. **第 3.4 节的收入测算是假设性推演**，不是预测。
4. **第 4.4 节的 6 个问题、第 5.4 节的健康线，都还没有被真实验证过** ——
   它们本身就是第 4 节调研计划要验证的对象。
5. 本文分析的是"课表 App"这个品类；如果产品最终定位改成"大学生活 App"，
   需求判断需要重做一遍。
