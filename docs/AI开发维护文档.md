# 几微 AI 开发维护文档

这份文档写给后续接手项目的开发代理，也写给需要快速判断改动影响的人。它不是产品宣传文案。所有“已完成”都必须以源码和实测为准，路线图里的内容不能直接当成成品。

## 接手前必须做的事

1. 先读 `AGENTS.md`；
2. 再读 `docs/HANDOVER.md` 的最后一节和未修复问题；
3. 查看 `git status`，不要覆盖用户已有的未提交改动；
4. 需要理解产品方向时读 `README.md`、`docs/项目介绍与规划.md` 和 `docs/ROADMAP.md`；
5. 需要改模型或边界时读 `docs/ARCHITECTURE.md` 和 `docs/DECISIONS.md`。

## 当前真实产品边界

当前可用重点是课程表、今天、计划、待办、模块开关、本地保存、备份和示例数据。记账、笔记、AI 是预留模块。不要在能力列表、README 或交接文档中把占位页描述成可用功能。

核心产品判断是“今天工作台”：每个新功能都要说明它如何帮助用户知道今天先做什么。新增入口前先检查是否能作为今天页的卡片、筛选条件或下一步行动呈现。

## 代码分层纪律

- `packages/core` 只放纯模型和纯函数，不依赖浏览器、React、Dexie 或文件系统；
- `packages/data` 负责仓储、Dexie、备份、学期和作息服务；
- `packages/ui` 只放跨模块通用 UI 和模块契约；
- `packages/platform` 负责通知、文件、持久化等设备能力；
- `apps/web` 负责 React 页面、外壳和模块装配；
- 页面通过 `useJiwei().repos` 和 data 服务读写，禁止直接使用 Dexie；
- 功能模块之间不要互相导入；跨模块共享逻辑放到 core、data 或 shared；
- 时间和周次计算只能复用 core；
- `refresh()` 只增加 `dataVersion`，不会自动重建课次；写入课程、学期、作息或调整后按需调用重建。

## 数据安全规则

- `Block` 是模板，`Occurrence` 是派生结果；编辑课程应保留原 `id` 和 `createdAt`；
- 正常课和调入课是 `normal`，调出课是 `moved`，停课是 `cancelled`；是否上课使用 `isOccurrenceActive()`；
- 备份恢复要先校验日期、引用和派生课次，再提交数据；失败不能覆盖原数据；
- 恢复后要同步 Zustand 中的选中学期和页面状态；
- 删除学期或课程时要检查调整、提醒、笔记等引用；
- 不改变旧备份字段、ID 规则和相对路径配置，除非同时提供兼容迁移；
- 模块关闭只隐藏入口，不删除已有数据。

## 计划、待办和今天的长期方向

不要继续维护两套互不相干的事项数据。统一事项模型至少需要考虑：

- `status`：收件箱、下一步、进行中、已完成、已归档；
- `priority`：用户可理解的优先级；
- 时间规则：截止日、日期区间、每周重复、无期限；
- `sourceId`：来自课程、导入、AI 或用户手动输入；
- 可选的课程、项目、空间关联。

迁移时先保持旧 `Block` 数据可读，再逐步让计划页、待办页和今天页共享服务层。不要为了“统一”一次性破坏现有用户数据。

## AI 开发边界

AI 的第一阶段是候选内容生成器，不是自动写库机器人：

1. 接收用户主动提供的文字、图片或文件；
2. 生成带来源和置信提示的候选课程、事项或账目；
3. 在界面上展示预览和可编辑字段；
4. 用户确认后调用现有导入/保存服务；
5. 记录可撤销的写入结果。

AI 失败、无网络或额度用尽时，手动录入仍必须可用。不得把个人课程表或账目静默上传到第三方服务，也不得在没有用户确认时覆盖已有数据。

## UI 和交互维护规则

- 首页优先展示今天、当前/下一节和需要执行的事项；
- 功能很多时使用分组、开关和渐进展开，不把所有按钮平铺；
- 输入框至少保留手机可用的触控尺寸，避免 iOS 输入时页面缩放；
- 弹层有明确关闭方式，关闭按钮固定但不遮挡内容；
- 页面切换保留轻量过渡，并尊重减少动态效果设置；
- 未开放功能必须显示“尚未开放”及预计阶段，不要让用户误以为按钮失效；
- 示例数据必须可重复导入，不能每次点击都复制一套数据。

## 每次代码改动后的验证

在仓库根目录依次运行：

```powershell
pnpm typecheck
pnpm test
pnpm build
pnpm smoke
```

涉及交互、恢复、刷新、离线或手机布局时，还要做浏览器验证，并在 `docs/HANDOVER.md` 写明是否覆盖了真机。纯文档改动至少检查 UTF-8、链接和 `git diff --check`。

## 记录和提交纪律

- 用户没有授权时不推送 GitHub、不部署、不使用 `pnpm save`；
- 不改写历史交接记录来掩盖旧问题；
- 每次完成后在 HANDOVER 追加日期、改动、检查结果和未验证边界；
- 产品能力变化同步 README/ROADMAP；模型或关键选择同步 ARCHITECTURE/DECISIONS；
- 报告结果时先说用户能看到的变化，再说技术实现和验证结果。

## 当前最值得优先做的工作

下一步优先完善 M5 的统一事项服务：先统一完成、延期、优先级和课程关联，再考虑记账。不要同时启动 AI 识图、云同步和插件运行时。它们必须建立在本地数据模型稳定、导入预览可靠和失败可恢复的基础上。
